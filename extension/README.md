# Chrome 확장 (LLM Gateway Guard)

웹 ChatGPT(chatgpt.com)와 Claude(claude.ai)에서 프롬프트를 보내기 직전에 로컬 게이트웨이로 보내 민감정보를 가리고,
답변이 오면 화면에서만 원래 값으로 되돌립니다. LLM API 키는 필요 없습니다. 직원은 평소처럼 자기 계정으로 웹을 씁니다.
빌드 도구 없이 바로 로드되는 순수 JS(Manifest V3)입니다.

## 설치 (개발용)

1. 게이트웨이를 먼저 띄웁니다 (루트 README의 "실행"). 기본 주소 `http://localhost:8000`.
2. Chrome에서 `chrome://extensions` 를 열고 오른쪽 위 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다** → 이 `extension/` 폴더를 선택합니다.
4. 도구 모음의 확장 아이콘을 눌러 연결 상태를 확인하고, 적용할 산업 템플릿을 고릅니다.
5. chatgpt.com 또는 claude.ai에서 `kim@corp.co.kr` 같은 문장을 보내 봅니다. 전송 직전 입력창이 `[이메일_1]`로 바뀌고, 답변 속 자리표시자는 화면에서 원래 값으로 보입니다. 아이콘의 숫자 배지는 그 탭에서 가린 항목 수입니다.

## 동작

| 파일 | 역할 |
|---|---|
| `content.js` | 입력창의 Enter / 전송 버튼을 가로채 가리고, 답변의 `[유형_n]`을 복원. **사이트별 선택자는 파일 맨 위 `SITES` 표**에 있음 |
| `ui.js` | 화면 안에 뜨는 것 전부 (검토 창, 차단·연결 끊김 창, 상태 칩, "N개 바꿔서 보냄" 버튼과 내역 서랍, 안내 띠, 토스트). Shadow DOM 안에 있어 사이트 CSS와 섞이지 않고, 페이지·서버에서 온 글자는 모두 `textContent`로만 넣음 |
| `lib.js` | 화면 없는 순수 함수 (자리표시자 짝짓기, 마스킹 `홍*동`, 대체어 치환, 유지 가능 항목 판단). `node --test extension/test/*.test.js` 로 검증 |
| `background.js` | 게이트웨이 호출 대행 (content script는 페이지 CORS를 받으므로 서비스 워커가 대신 호출). 탭별 vault id를 세션 저장소에 보관하므로 새로고침해도 복원되고, 웹 페이지에는 노출되지 않음 |
| `popup.html/css/js` | 켜기/끄기, 연결 상태 3가지(연결됨/끊김/꺼짐), 산업 템플릿, 오늘 숫자, 전체 보기·관리자 콘솔 링크, 연결 설정 |
| `dev/` | 개발용 가짜 채팅 화면·팝업 미리보기 (아래) |

### 사용자 화면 (디자인 캔버스 U1–U6)

| 화면 | 구현 |
|---|---|
| U1 검토 창 | 가리기 대상이 있으면 보내기 전에 뜸. 항목마다 `자리표시자 / 대체어 / 그대로 두기`를 고르고 아래 미리보기가 바로 바뀜. 시크릿·주민번호·외국인등록번호는 그대로 두기 불가 |
| U2 차단·연결 끊김 | 차단 창(해당 부분 선택하기 / 예외 요청), 서버 연결 끊김 창(다시 시도). 둘 다 입력한 글은 지우지 않음 |
| U3 답변 복원 (실험 기능, **기본 꺼짐**) | 켜면 자리표시자를 화면에서만 원래 값으로, 만료·못 찾음·새 개인정보 안내 띠. 꺼 두면 말풍선과 AI 응답이 AI가 실제로 받은 모양(`[사람_1]`) 그대로 보임 |
| 안내 문장 | 자리표시자가 실제로 나가는 글 끝에 "[종류_번호] 모양은 가려 둔 자리표시자니 그대로 써 달라"는 한 줄을 붙임(없으면 AI가 `[사람_1]`을 빈칸으로 읽고 되물음). 내 말풍선에서는 숨김. 팝업 `연결 설정`에서 끌 수 있음 |
| U6 입력창 위 칩 | 검사 중 / 괜찮음 / 가릴 것 있음 칩, "N개 바꿔서 보냄" 버튼 → 오늘 바꾼 내역 서랍(마스킹된 값만, 이 기기에 7일) |
| 팝업 | 켜기/끄기, 상태, 산업, 오늘 숫자, 연결 설정 |
| 내 계정 연결 | 팝업의 **내 계정**에 관리자가 승인한 회사 메일을 넣으면 이 브라우저가 그 구성원에 연결돼서, 관리자 콘솔 기록에 보낸 사람의 이름과 부서가 남습니다. 스스로 밝히는 방식이라 아무 권한도 주지 않고, 언제든 끊을 수 있습니다 |
| 예외 요청하기 | 막힘 창의 **예외 요청** 버튼이 새 탭 없이 채팅 화면 위에 요청 창을 띄움(항목·사이트 미리 채움, 기간 1회/1시간/24시간, 사유 20자 이상). 보내면 같은 기록이 만들어지고 답은 아래 알림으로 옴. 프롬프트 글은 보내지 않음 |
| 예외 요청 알림 | 관리자가 승인·반려하면 채팅 화면 위쪽 가운데에 알림 카드가 쑥 나타났다가 몇 초(승인 7초·반려 10초, 마우스를 올리면 멈춤) 뒤 저절로 사라짐(화면을 막지 않음). 채팅 화면이 앞에 없으면 시스템 알림. 승인된 예외가 있는 동안 입력창 **왼쪽**에 모래시계 칩 하나(가장 먼저 끝나는 것의 남은 시간, `59:03`). 누르면 **승인된 규칙 전체**가 항목·사이트·기간·관리자 메모와 각자의 남은 시간으로 펼쳐지고, 1회 허용은 쓰는 즉시 사라짐. 시간 표기(`59:03` / `59분 03초`)는 팝업 연결 설정에서 고름 |

- 게이트웨이가 꺼져 있거나 차단(403)이면 **전송하지 않습니다** (fail closed). 팝업에서 끄면 그대로 통과시킵니다.
- 한글 IME 입력 중 Enter(`isComposing`)는 전송으로 취급하지 않습니다.
- 사이트 표(`SITES`)의 입력창 선택자가 하나도 안 맞으면 "안전 모드"로, 편집 가능한 아무 칸이나 입력창으로 보고 Enter와 보내기 버튼을 모두 검사합니다. 보내기 버튼을 못 찾으면 확인을 마친 글을 입력창에 넣어 두고 사용자의 Enter를 한 번 더 기다립니다 (스크립트가 만든 Enter는 실제 사이트가 무시하기 때문).
- 답변·말풍선의 자리표시자는 특정 컨테이너 선택자에 기대지 않고 **화면 전체**에서 찾아 복원합니다(입력창·확장 UI 제외). ChatGPT가 답변을 `data-message-author-role` 없이 별도 렌더러(`data-dil-message-id`)로 그리고 자리표시자를 `<code>` 안에 넣는 화면에서 복원이 안 되던 문제를 이렇게 풀었습니다 (`dev/fake-chat.html?reply=dil`로 재현). 내 글인지는 선택자 또는 실제로 내보낸 문장과의 일치로 판단합니다.
- 보내기 화살표는 사이트 표의 선택자로 먼저 찾고, 못 찾으면 모양으로 판단합니다(입력창 옆의 submit 버튼, 또는 이름에 send/submit/보내기/전송이 들어간 버튼). 폼 제출(`submit`)도 가로챕니다. 모르는 버튼이 검사 없이 글을 내보내는 일이 없게 하기 위해서입니다 (`dev/fake-chat.html?layout=arrow`로 재현).
- 글을 붙여넣거나 끌어다 놓거나 스크립트로 바뀌어도(입력 이벤트가 없어도) 입력창 위 칩이 바로(0.1~0.3초) 갱신됩니다.
- 미리보기(`/v1/analyze`)가 HTTP 오류(401 등)로 실패해도 보호는 그것에 기대지 않습니다. 이 경우 `/v1/sanitize`로 찾은 것을 모두 자리표시자로 바꿔 보내고 "미리보기를 받지 못해서(401) …" 안내를 띄웁니다. `sanitize`까지 실패하면 아무것도 보내지 않고, 토스트에 상태 코드와 서버 메시지가 나옵니다. 서버에 연결할 수 없을 때(상태 0)는 기존처럼 다시 시도/취소를 묻습니다.
- "확인한 글을 넣어 뒀으니 Enter를 한 번 더" 허용은 20초 동안, 그 글이 그대로 있을 때만 유효합니다. 다음 글로 넘어가지 않습니다. 항목별 선택(자리표시자/대체어/그대로 두기)은 글마다 항상 처음 상태(자리표시자)에서 시작합니다.
- 입력창은 `contenteditable`과 `<textarea>` 둘 다 읽습니다.
- 팝업 `연결 설정`의 "이 탭 상태"에서 이 탭에 확장이 적용됐는지, 입력창·보내기 버튼·답변 영역을 표의 선택자로 찾았는지, 지금까지 가로챈 전송이 몇 번인지 봅니다. 못 찾았으면 화면에 있는 입력창·버튼 후보가 같이 나와 선택자를 고칠 때 씁니다.
- 매핑(vault)은 게이트웨이 메모리에만 있고 30분 안 쓰면 사라집니다. 사라지면 새 매핑으로 이어갑니다 (이전 답변의 자리표시자는 복원되지 않음).

## 예외 요청의 답이 채팅 화면으로 돌아오는 흐름

1. 차단 창의 **예외 요청**을 누르면 새 탭 없이 채팅 화면 위에 요청 창이 뜹니다(항목·사이트가 미리 채워지고, 기간과 사유만 고름). 요청은 이 확장이 가진 번호(로그인이 아니라 브라우저마다 만든 무작위 번호)로 저장돼서, 답과 남은 시간도 같은 브라우저에만 보입니다.
2. 요청은 게이트웨이에 저장되고 관리자 콘솔 "예외 요청"에 나타납니다. 관리자가 승인(허용 시간, 메모)하거나 반려(메모)합니다.
3. 채팅 화면(chatgpt.com, claude.ai)이 20초마다 내 요청을 확인해서, 새 답이 있으면 **한 번만** 알려 줍니다: "조성비 요청이 승인됐어요 · 오늘 17:32까지 (24시간)" 아래에 **관리자 메모**가 따로 한 줄 나옵니다.
4. 승인이 진행 중인 동안은 입력창 위에 **남은 시간이 1초마다 줄어드는 줄**이 떠 있고(칩은 `59:03` 형식), 끝나면 사라지면서 "예외로 허용된 시간이 끝났어요"가 뜹니다. 팝업의 "내 예외 요청"에도 같은 정보가 실시간으로 보입니다.

알려 준 답은 `chrome.storage.local.exAnnounced`에 기억해서 탭을 여러 개 열거나 새로고침해도 두 번 뜨지 않습니다.
승인은 알림에 그치지 않고 실제로 적용됩니다. 확장이 `/v1/sanitize`·`/v1/analyze`에 브라우저 번호를 실어 보내고, 서버가 그 번호로 승인된 요청을 찾아 **요청에 적힌 항목 종류만**, 정해진 시간 동안(사이트가 적혀 있으면 그 사이트에서만) 가리지도 막지도 않고 그대로 내보냅니다.

- 통과시키면 "예외 … 허용된 항목을 그대로 보냈어요 · 남은 시간 …"이 뜹니다. 1회 승인은 "1회 허용을 사용했어요 · 이 승인은 끝났어요"가 뜨고, 팝업 목록에는 "사용 완료"로 남습니다.
- 같은 종류의 항목은 한 글 안에서 모두 통과합니다. 한 건만 골라서 허용하지는 않습니다.
- 브라우저 번호는 로그인이 아니라서, 번호를 아는 사람은 같은 승인을 쓸 수 있습니다.

## 확장 없이 로직만 확인하기 (dev 페이지)

로그인 없이 가로채기 → 가림 → 복원 흐름을 확인하는 가짜 채팅 화면입니다. 게이트웨이를 `UPSTREAM_MODE=mock`으로 띄운 뒤:

```bash
python -m http.server 5173 --directory extension
```

`http://localhost:5173/dev/fake-chat.html?industries=cosmetics` 를 열고 입력창에 문장을 쓰고 Enter를 누르면, 아래 `pre`에 "외부로 나가는 문장"이 보이고 가짜 답변이 복원돼 나타납니다. `?enabled=0`으로 열면 끄기 상태를 흉내냅니다.
(`localhost:5173`은 게이트웨이 CORS 기본 허용 목록에 있습니다.)

`dev/popup-preview.html` 은 실제 `popup.html` 을 같은 서버에서 열어 봅니다 (`?enabled=0`, `?gateway=http://localhost:9`, `?industries=cosmetics`).

## 가짜인 것 (연결 전)

서버에 아직 없는 기능이라 화면만 있습니다. **실제 보호로 보이지 않도록** 모두 꼬리표를 달고 기본은 꺼져 있습니다.

| 무엇 | 어떻게 가짜인가 | 지울 때 |
|---|---|---|
| 대체어(별칭) | 팝업/서버에 관리 화면이 없어 `lib.js`의 `ALIASES` 고정 목록. 선택은 탭 세션 안에서만 기억 | 관리자 콘솔의 대체어 목록 API |
| 가리기 검토 창이 뜨는 조건 | `/v1/analyze` 가 규칙별 `ask/exc/notify` 옵션을 알려주지 않아, 가릴 항목이 있으면 모두 검토 창을 띄움 | analyze 응답에 규칙 옵션 추가 |

서버에 필요한 것: 규칙별 옵션 노출, 관리자가 관리하는 대체어 목록, 사용자 신원(누가 보냈는지). 파일 검사와 가입·로그인 화면은 서버에 기능이 없어 화면도 없앴습니다.

## 검증 상태 (솔직하게)

- 가짜 채팅 화면에서 확인함: 가림, 답변 복원, 검토 창(항목별 선택·미리보기·키보드·Esc), 차단 시 전송 안 됨, 게이트웨이가 꺼졌을 때 전송 안 됨, 한글 조합 중 Enter, 끄기 스위치, 팝업 3상태. 순수 함수는 `node --test extension/test/*.test.js`.
- ChatGPT처럼 답변 옆에 카드(메일 초안 등)가 따로 그려지고 글이 스트리밍으로 바뀌는 구조를 `dev/fake-chat.html?reply=chatgpt`로 흉내 내어, 답변 문단과 카드 안의 자리표시자가 모두 복원되는 것을 확인함. 실제 ChatGPT 화면에서는 아직 확인하지 못함.
- **확인하지 못함**: 실제 chatgpt.com / claude.ai 화면, 확장으로 로드했을 때의 팝업·배지·`chrome.storage.session`, 한글 IME 입력. claude.ai 선택자는 추정값입니다.
- 조원 A가 실제 사이트에서 돌려보고 `content.js`의 `SITES` 표만 고치면 됩니다. 증상별 확인법:
  - 전송이 그냥 나감 → `composer`/`send` 선택자가 안 맞음 (개발자 도구에서 요소를 찍어 확인)
  - 가려지긴 하는데 전송이 안 됨 → 사이트가 `insertText` 입력을 인식하지 못하거나 `send` 버튼 선택자가 틀림
  - 답변이 복원되지 않음 → `reply` 선택자가 틀림

## 한계

- 확장은 사용자가 끌 수 있으므로 **강제 수단이 아닙니다.** 강제는 네트워크/기기 정책으로 합니다 (루트 README의 "차단 방향" 참고).
- 데스크톱 앱(ChatGPT/Claude 앱)은 브라우저 밖이라 이 확장으로 다룰 수 없습니다.
- 이미지/파일 첨부는 **가리지 않습니다.** 텍스트 입력만 처리합니다.
- 게이트웨이 주소는 팝업의 "게이트웨이 주소"에서 바꿉니다 (기본 `http://localhost:8000`). 내 PC 밖의 서버는 `https`만 받고, 저장할 때 Chrome이 그 주소에 대한 권한을 묻습니다. 배포 방법은 `docs/DEPLOY.md`.

## 답변 복원 (가린 값을 화면에서 되돌리는 방법)

> **기본은 꺼짐입니다.** 메일 전송 같은 도구 호출과 결합될 때의 구조적 한계가 있어 실험 기능으로 두었고, 꺼 두면 화면에는 AI가 실제로 받은 자리표시자 상태가 그대로 보입니다(가림 처리를 눈으로 보여 주기 좋습니다).
> - **끄고 켜기**: 팝업의 **복원 표시 (실험 기능)** 체크박스. 켜면 열려 있는 탭에서 바로 복원하고, 끄면 이미 되돌린 글은 새로고침해야 다시 자리표시자로 보입니다.
> - **모두의 기본값 바꾸기**: `lib.js`의 `DEFAULT_RESTORE = false` 한 줄(팝업 설정이 있으면 그쪽이 우선).
> - 꺼졌을 때 막히는 곳: 본문 복원, 입력칸 복원(메일 카드 등), iframe 복원, 모양이 바뀐 자리표시자 복원 제안, "모델이 자리표시자를 쓰지 않았어요" 안내, 그리고 `background.js`의 `restore` 요청(원문 그대로 돌려줌). 복원 코드는 그대로 있고 호출만 막힙니다.
> - 꺼져 있어도 **그대로**인 것: 가림, 서버 탐지, 확인 창, 등록된 대체어, 차단, 답변 속 새 개인정보 스캔, 사용자 말풍선의 `(안내: …)` 문구 숨김(말풍선에는 쓴 글만 보이게 하는 기존 동작. 이 문구는 실제 전송 글에는 들어 있습니다).
> - 가짜 채팅 화면에서는 `fake-chat.html?restore=1`로 켠 상태를 볼 수 있습니다.

가린 값은 아래 순서로 되돌립니다. 앞의 것이 되면 서버를 부르지 않습니다.

1. **이 탭이 기억하는 원래 값**: 보낼 때 `[사람_1]` ↔ 홍길동을 탭 세션 저장소(메모리, 디스크에 안 씀, 브라우저를 닫으면 사라짐)에 1시간 기억합니다. 게이트웨이를 재시작했거나 30분이 지나 서버가 매핑을 잊어도 복원됩니다.
2. **등록된 대체어**와 **게이트웨이의 매핑(vault)**.
3. 화면 어디든 찾습니다: 답변 문단, 말풍선, 사이트가 따로 그리는 카드(메일 초안 등), **입력칸 값**(카드의 받는 사람 칸 같은 것), `all_frames`로 **iframe 안 카드**(ChatGPT가 샌드박스에서 그리는 경우, `*.oaiusercontent.com` 포함). 모양이 바뀐 자리표시자(`[이메일 1]`)는 "복원할까요?"로 묻습니다.
4. **카드의 보내기 버튼**(예: ChatGPT에 연결된 메일 앱의 "보내기")을 누르면 한 번 확인합니다. 화면에 원래 값을 보여 줘도 사이트가 카드 뒤에 쥔 값은 `[이메일_1]` 그대로일 수 있기 때문입니다. 입력칸은 원래 값으로 채우므로 그 칸에서 보내는 카드는 실제 주소로 나갑니다.

한계: 모델이 도구 호출(메일 보내기)을 사이트 서버 안에서 바로 실행하는 경우, 그 인자는 브라우저를 거치지 않아 확장이 바꿀 수 없습니다. 이때는 카드의 값을 확인하고 직접 고쳐 보내야 합니다. iframe 복원은 사이트가 어느 주소로 카드를 그리는지에 달려 있어 실제 사이트에서는 아직 확인하지 못했습니다 (가짜 채팅 화면의 iframe에서만 확인).
