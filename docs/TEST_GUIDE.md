# 직접 돌려보기

게이트웨이, 관리자 콘솔, Chrome 확장을 내 PC에서 한 번에 켜고 확인하는 방법입니다. API 키는 필요 없습니다.

## 1. 켜기

준비물은 Windows, Python 3.11 이상, Node.js 22 이상(LTS), Chrome입니다. 저장소 폴더에서 아래를 실행하세요.

```bash
.\dev.bat seed
```

`seed`를 붙이면 가짜 요청 15건이 들어가서 콘솔 그래프에 숫자가 보입니다. 빈 화면에서 시작하려면 `.\dev.bat`만 실행하세요. PowerShell에서는 앞의 `.\`가 꼭 필요합니다.
처음 한 번은 패키지를 설치해서 몇 분 걸립니다. 끝나면 창이 두 개 열리고 브라우저에 로그인 화면이 뜹니다.

| 창 | 주소 |
|---|---|
| 게이트웨이 | http://localhost:8000 (API 문서는 `/docs`) |
| 관리자 콘솔 | http://localhost:3000 |

로그인은 `admin@example.com` / `test1234`입니다. 연습용 가짜 계정이고 서버가 확인하는 로그인이 아닙니다.
끌 때는 열린 두 창을 닫으면 됩니다. 처음으로 되돌리려면 둘 다 끈 뒤 `data` 폴더를 지우세요(기록과 정책이 사라집니다).

## 2. 콘솔에서 진짜인 것과 예시인 것

"예시 값" 배지가 붙은 곳은 서버에 아직 없는 기능이라 가짜 숫자입니다.

| 화면 | 상태 |
|---|---|
| 01 개요, 02 실시간 모니터링, 03 기록, 04 분석 리포트 | 진짜 (서버 기록, 이상 징후는 기록에서 계산해 시크릿 반복 차단·가림 급증 등을 보여줌). 부서별 표, 교육 대상, 정기 리포트, "잘못 찾은 비율"은 예시 |
| 05 정책 엔진 | 진짜. 규칙을 만들고, 승인하고, 적용하면 다음 요청부터 바뀝니다 |
| 05-2 기본 규칙 | 진짜. 끄면 그 규칙은 더 이상 가리지 않습니다 |
| 06 예외 요청, 07 구성원·가입 승인, 08 설정, 로그인, 포털 | 예시 (새로고침하면 처음으로 돌아감) |

## 3. 규칙을 직접 만들어 보기

1. 정책 엔진에서 "새 규칙 만들기". 규칙명에 `미공개 프로젝트`, 단어 목록에 `프로젝트 블루문`, 이름표에 `[프로젝트_n]`을 넣고 "규칙 추가"를 누릅니다.
2. 오른쪽의 "미리 시험하기"에 `프로젝트 블루문 일정`을 넣고 시험하면 가려져 보입니다. 아직 초안이라 실제 요청에는 적용되지 않은 상태입니다.
3. 오른쪽 위 "변경 1건 승인하고 적용" → "승인하고 적용"을 누릅니다. 이제부터 모든 요청에 적용됩니다.
4. 터미널에서 실제 게이트웨이를 통과시켜 확인합니다.

```bash
.venv\Scripts\python scripts\try_text.py "프로젝트 블루문 일정 공유"
```

`나가는 문장: [프로젝트_1] 일정 공유`가 나오면 됩니다. 산업 템플릿을 같이 시험하려면 뒤에 `cosmetics` 같은 이름을 붙이세요.

5. 규칙을 바꿀 때마다 새 버전이 생기고, 옛 버전으로 되돌릴 수 있습니다(API는 `docs/API.md`의 회사 정책). 05-2 기본 규칙에서 "이메일"을 끄고 적용하면 메일 주소가 가려지지 않습니다. 확인한 뒤 다시 켜세요.

## 4. Chrome 확장 설치와 사용

1. 게이트웨이가 켜져 있어야 합니다(1번).
2. 주소창에 `chrome://extensions`를 입력하고 오른쪽 위 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**를 눌러 저장소의 `extension` 폴더를 고릅니다. 코드를 바꾼 뒤에는 이 화면에서 확장의 새로고침 버튼을 눌러야 합니다.
4. 도구 모음의 확장 아이콘(퍼즐 조각에서 고정)을 누릅니다. "게이트웨이 연결됨"이 보이는지 확인하고, 쓸 **산업 템플릿**을 체크합니다. 체크한 산업만 적용됩니다. 안 고르면 기본 규칙만 돌아갑니다.
5. chatgpt.com 또는 claude.ai에서 평소처럼 글을 쓰고 Enter(또는 보내기 버튼)를 누릅니다. 보내는 순간 입력창의 글이 `[이메일_1]` 같은 이름표로 바뀐 채 나갑니다.
6. 답변에 이름표가 있으면 화면에서만 원래 값으로 보입니다. 아이콘의 숫자는 그 탭에서 가린 항목 수입니다.
7. 콘솔의 03 기록에서 방금 보낸 건을 찾아보세요. 사이트(`chatgpt.com`)와 확장 버전이 같이 남습니다. 원래 값은 어디에도 저장되지 않습니다.

팝업의 "가림막 켜기"를 끄면 그대로 전송됩니다. 게이트웨이가 꺼져 있으면 전송을 막고 경고창을 띄웁니다(안전 쪽으로 실패).

로그인 없이 확장 로직만 보고 싶으면 [extension/README.md](../extension/README.md)의 가짜 채팅 화면을 쓰세요.
실제 chatgpt.com, claude.ai 화면에서 입력창과 보내기 버튼을 제대로 찾는지는 아직 확인하지 못했습니다. 안 될 때의 증상별 대처도 그 문서에 있습니다.

## 6. 안 될 때

| 증상 | 확인 |
|---|---|
| `dev.bat`이 Python/Node가 없다고 함 | 각각 설치한 뒤 새 터미널에서 다시 실행 |
| 콘솔이 "검사 서버에 연결하지 못했어요" | 게이트웨이 창이 열려 있는지, http://localhost:8000/health 가 열리는지 |
| 포트 8000 또는 3000이 이미 사용 중 | 이전에 켠 창을 닫기 |
| 콘솔 그래프가 비어 있음 | 요청이 아직 없는 것. `.\dev.bat seed`로 넣거나 확장으로 몇 번 보내기 |
| 규칙을 적용했는데 안 바뀜 | "변경 n건 승인하고 적용"까지 눌렀는지. 확장은 산업 템플릿을 체크했는지 |
| 확장이 그냥 전송함 | 사이트 화면 구조가 달라 입력창을 못 찾은 경우. `extension/README.md`의 증상표 참고 |

## 7. 아직 안 되는 것

- 누가 보냈는지 서버가 모릅니다. 그래서 부서별 규칙, 사용자별 예외, 구성원 관리는 화면만 있습니다.
- 콘솔 로그인은 가짜이고, 서버 쪽 인증은 `GATEWAY_ADMIN_TOKEN` 하나뿐입니다.
- 파일·이미지 첨부는 가리지 않습니다. 입력창의 글자만 검사합니다.
- 이름은 "고객 홍길동", "김철수 대리"처럼 직함이 붙어야 찾습니다. 직함 없는 이름은 아직 찾지 못합니다.
- 데스크톱 앱(ChatGPT, Claude 앱)은 브라우저 확장으로 다룰 수 없습니다.
