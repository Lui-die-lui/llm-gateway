# 배포하기

내 PC가 아니라 인터넷에 올려서 팀원이나 심사위원이 접속하게 하는 방법입니다. 코드로 할 수 있는 준비는 끝나 있고, 아래 단계는 계정이 필요해서 직접 눌러야 합니다.

## 먼저 알아둘 것: 올릴 곳이 둘입니다

```
직원 브라우저 ── 확장 ──▶ 게이트웨이(서버) ◀── 관리자 콘솔(웹 화면)
                          기록과 정책을 저장
```

| 올릴 것 | 어디에 | 이유 |
|---|---|---|
| 관리자 콘솔 | Vercel | 화면 파일뿐이라 정적 호스팅으로 충분합니다 |
| 게이트웨이 | Render, Railway, Fly.io 같은 Docker 호스팅 | 기록을 저장할 디스크가 있고 계속 켜져 있어야 합니다. Vercel에는 못 올립니다 |
| 확장 | 내 Chrome에 개발자 모드로 설치 | 주소만 배포한 서버로 바꿉니다 |

순서는 **게이트웨이 → 콘솔 → 확장**입니다. 게이트웨이 주소가 있어야 나머지를 맞출 수 있습니다.
화면 이름과 요금은 호스팅 회사가 바꿀 수 있어서, 아래 이름과 다르면 비슷한 항목을 찾으세요.

## 1. 게이트웨이 올리기 (Render 기준)

1. render.com에 가입하고 GitHub 계정을 연결합니다. org 저장소(`llm-gateway-busan`)에 접근 권한을 주는 단계에서 org 소유자의 승인이 필요할 수 있습니다.
2. New → **Web Service** → 이 저장소 선택. Language는 **Docker**로 둡니다. 저장소 루트의 `Dockerfile`을 그대로 씁니다.
3. 인스턴스는 **1개**로 둡니다. 2개 이상으로 늘리면 안 됩니다(정책이 프로세스마다 따로 기억됩니다).
4. **Disk**를 추가하고 Mount Path를 `/app/data`로 합니다. 이걸 빼면 서버가 재시작될 때마다 기록과 정책이 사라집니다. 디스크는 무료 플랜에서 안 될 수 있습니다. 발표용으로 잠깐 쓰는 거라면 디스크 없이도 돌아가지만 데이터는 날아간다고 생각하세요.
5. **Environment** 항목에 아래 값을 넣습니다.

| 이름 | 값 |
|---|---|
| `UPSTREAM_MODE` | `mock` (API 키 없이 동작) |
| `GATEWAY_ADMIN_TOKEN` | 길고 아무도 모르는 문자열. 콘솔에서 입력할 비밀번호가 됩니다 |
| `GATEWAY_CORS_ORIGINS` | 2번에서 받을 콘솔 주소. 지금은 비워 두고 콘솔을 올린 뒤에 채웁니다 |

6. 배포가 끝나면 `https://○○.onrender.com` 같은 주소가 생깁니다. 주소 뒤에 `/health`를 붙여 열었을 때 `{"status":"ok"}`가 나오면 성공입니다.

`GATEWAY_ADMIN_TOKEN`을 비워 두면 서버 로그에 경고가 뜹니다. 그 상태로 공개하면 누구나 정책을 바꾸고 기록을 볼 수 있습니다.

## 2. 콘솔 올리기 (Vercel)

1. vercel.com에 가입하고 GitHub를 연결합니다. org 저장소는 org 소유자가 Vercel 앱 설치를 승인해야 목록에 보입니다. 무료(Hobby) 플랜이 org의 private 저장소를 받아주지 않으면, 팀원 개인 계정으로 저장소를 포크해서 올리면 됩니다.
2. Add New → Project → 이 저장소 선택.
3. **Root Directory**를 `frontend`로 바꿉니다. Framework는 Vite로 자동 선택됩니다. `frontend/vercel.json`이 화면 경로를 처리합니다.
4. **Environment Variables**에 `VITE_GATEWAY_URL`을 추가하고 값은 1번에서 받은 게이트웨이 주소(끝에 `/` 없이)로 합니다. 이 값은 빌드할 때 들어가므로, 나중에 바꾸면 다시 배포해야 합니다.
5. Deploy를 누릅니다. `https://○○.vercel.app` 주소가 생깁니다.
6. Render로 돌아가 `GATEWAY_CORS_ORIGINS`에 이 Vercel 주소를 넣고 저장합니다(서버가 다시 시작됩니다). 이걸 빼면 콘솔이 서버를 못 부릅니다.
7. 콘솔을 열면 처음에 관리자 토큰 입력 화면이 나옵니다. 1번에서 정한 `GATEWAY_ADMIN_TOKEN` 값을 넣으세요. 탭을 닫으면 지워집니다.

콘솔 로그인(`admin@example.com`)은 연습용 가짜라서 보호 장치가 아닙니다. 실제로 막아주는 건 관리자 토큰뿐입니다.

## 3. 확장을 배포한 서버에 연결하기

1. `chrome://extensions`에서 확장을 새로고침합니다(코드가 바뀌었습니다).
2. 확장 아이콘 → **게이트웨이 주소**에 1번의 주소를 넣고 저장 → Chrome이 묻는 권한을 허용합니다.
3. "게이트웨이 연결됨"이 보이면 chatgpt.com, claude.ai에서 평소대로 쓰면 됩니다.

내 PC 밖의 서버는 `https://` 주소만 받습니다. 프롬프트가 평문으로 나가면 가리는 의미가 없기 때문입니다.

## 4. 올리기 전에 확인할 것

- [ ] `/health`가 열린다
- [ ] `GATEWAY_ADMIN_TOKEN`을 설정했다
- [ ] `UPSTREAM_MODE=mock`이거나, 실제 키를 넣었다면 서버 주소를 아무에게나 공개하지 않았다 (호출하는 사람을 확인하는 장치가 아직 없어서, 주소를 아는 사람이 내 키로 LLM을 부를 수 있습니다)
- [ ] 콘솔이 데이터를 불러온다 (안 되면 `GATEWAY_CORS_ORIGINS`와 `VITE_GATEWAY_URL`을 확인)
- [ ] 확장 팝업에 "게이트웨이 연결됨"이 뜬다

## 5. 확인하지 못한 것

- 이 PC에는 Docker가 없어서 `Dockerfile`을 직접 빌드해 보지 못했습니다. 첫 배포가 여기서 막히면 빌드 로그의 마지막 오류를 알려주세요.
- Render, Vercel에 실제로 올려 보지는 못했습니다. 위 단계는 각 서비스의 일반적인 흐름 기준입니다.
- 콘솔의 프로덕션 빌드는 확인했습니다. 서버 주소가 빌드 결과에 들어가고 `localhost`는 남지 않습니다.
- 확장의 주소 설정은 문법만 확인했고 Chrome에 로드해서 눌러 보지는 못했습니다.

## 직원 PC마다 게이트웨이를 띄우는 방식이라면

서버 배포가 필요 없습니다. 각자 `.\dev.bat`으로 켜면 되고 확장은 기본값(`http://localhost:8000`) 그대로 씁니다.
다만 정책이 PC마다 따로 저장되어 회사 전체의 규칙을 한곳에서 관리할 수 없습니다.
