## 최신: 2026-11-02 · IP 주소를 키워드 없이도 가림

- 기본 규칙에 `IP주소`가 생겼습니다 (`app/detector.py`, 콘솔 기본 규칙의 "보안 정보"에 "IP 주소"로 표시). 0~255 네 칸으로 된 IPv4는 "IP", "서버" 같은 말이 없어도 가립니다 (처리: 가림).
- 예전에는 IT/개발 업종 템플릿의 `내부IP`(사설 대역만, 주변 40자에 키워드가 있어야 함)뿐이었고, 업종을 고르지 않으면 IP 보호가 전혀 없었습니다. 공인 IP도 안 잡혔습니다. 템플릿 규칙은 그대로 두었고, 겹치면 템플릿(`내부IP`)이 이깁니다.
- 건드리지 않는 것: `127.x`, `0.x`, `255.255.255.255`, 네 칸을 넘는 점 숫자(`10.0.19045.1`), `v`·`ver`·`version`·`버전` 바로 뒤 숫자(소프트웨어 버전). 한계: 앞에 그런 말이 없는 `1.2.3.4` 모양 버전은 IP로 보고 가립니다. IPv6는 아직 안 잡습니다.
- 템플릿이 범용 규칙을 얼마나 앞서는지 재는 시험(`generic_recall == 0`)은, 범용 규칙이 IP를 잡게 되어 `< 0.1`로 바꿨습니다.

## 최신: 2026-10-30 · 예외 요청이 실제로 적용되기까지 (PR #15 ~ #18)

**한 줄 요약**: 직원이 예외를 요청하고 관리자가 승인하면, 승인된 항목이 정해진 시간 동안 정말로 통과합니다. 채팅 화면에서는 승인·남은 시간·사용 완료를 알려 줍니다.

**서버**
- 승인 적용 (`app/exception_requests.py`의 `grants`, `spend`): 확장이 `/v1/sanitize`·`/v1/analyze`에 브라우저 번호(`client_id`)를 실어 보내면, 서버가 그 번호로 승인된 요청을 찾아 **요청에 적힌 항목 종류만**, 정해진 시간 동안(요청에 사이트가 있으면 그 사이트에서만) 가리지도 막지도 않고 내보냅니다.
  - 1회 승인은 실제로 내보낸 첫 전송에서 소진됩니다. 다른 항목 때문에 어차피 막힌 전송, 입력 중 미리보기(`analyze`)는 소진하지 않습니다.
  - 응답에 `exceptions`(어떤 승인을 썼는지, 1회인지, 남은 초)가 들어가고, 감사 기록에 `exception_id`가 남습니다. 요청 목록에는 `used`가 들어갑니다.
  - 한 가지 종류의 항목은 한 글 안에서 모두 통과합니다. 한 건만 골라 허용하지는 않습니다.
- 항목이 적히지 않은 요청은 승인할 수 없습니다 (422). 승인해도 아무것도 통과하지 않기 때문입니다.
- 요청 한도(1000건)는 대기 중인 요청만 세고, 처리된 지 180일 넘은 요청은 자동으로 지웁니다.
- #15: 아주 크거나 이상한 요청 하나로 서버가 멈추거나 500이 나던 문제를 고쳤습니다 (정규식이 파이썬 락을 쥔 채 오래 도는 문제, 잘못된 채팅 요청 모양은 500 대신 400).

**확장**
- 예외 요청 결과를 채팅 화면에 알립니다 (승인·반려, 관리자 메모, 끝나는 시각). 승인 중에는 남은 시간이 1초마다 줄어드는 줄이 뜨고, 팝업 목록에도 같이 보입니다.
- 승인된 항목을 쓰면 알림이 뜹니다. 1회는 "사용했어요 · 이 승인은 끝났어요", 시간제는 "남은 시간 …". 옛 "1회만 허용돼요" 줄은 사라지고 팝업 목록에는 "사용 완료"로 남습니다.
- 말풍선은 항상 아래 채팅 입력창 전체의 오른쪽 위에 붙습니다. ChatGPT 답변 안의 메일 카드에 글을 써도 검사 말풍선은 아래에 뜨고, 카드 안 Enter는 전송으로 가로채지 않습니다 (전송은 늘 아래 입력창 기준).
- 입력창과 보내기 단추를 고르는 방식을 정리했습니다 (`content.js`의 `siteComposer`).

**콘솔 (프론트)**
- 예외 요청 화면에 "적용 중인 승인" 목록: 요청자, 허용 항목, 대상, 기간, 남은 시간, 메모. 시간이 끝나거나 1회를 쓰면 사라지고, 위쪽 ACTIVE GRANTS 카드도 이 값을 씁니다.
- 기록 화면: 예외로 통과한 건에 "예외" 표시, 상세에 예외 승인 번호, 처리 단계에 "예외 승인 적용".
- 항목 없는 요청은 승인 버튼이 꺼지고 이유가 뜹니다. 7일 허용 안내문에서 실제로 없는 "CISO 추가 승인" 문구를 뺐습니다 (#18).

**알아 둘 것**
- 브라우저 번호는 로그인이 아니라서, 번호를 아는 사람은 같은 승인을 쓸 수 있습니다. 로그인 연동은 아직 계획에 없습니다.
- 사이트가 `chatgpt.com`으로 적힌 승인은 `chat.openai.com`에서는 적용되지 않습니다.
- 같은 브라우저가 1회 승인을 동시에 두 번 보내면 둘 다 통과할 수 있습니다 (실제로는 거의 없음).
- 감사 기록은 보관 기한 없이 쌓입니다. 한 건이 몇백 바이트라 지금 규모에서는 문제없습니다.
- 콘솔의 실시간·리포트·설정·구성원 화면과 예외 요청 화면의 일부 숫자는 아직 목업입니다.
- 서버 코드는 `main`이 바뀌어도 Railway에 자동으로 올라가지 않습니다. 배포가 필요하면 말해 주세요.
- 문서: `docs/API.md`(sanitize의 `client_id`), `extension/README.md`(예외 요청 흐름).
