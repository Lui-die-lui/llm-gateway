# 점검 결과와 남은 일

프론트가 합쳐진 시점(`b877cce`)의 `main`을 받아서 서버와 직접 붙여 보고 정리했습니다.
직접 돌려보는 방법은 [TEST_GUIDE.md](TEST_GUIDE.md)에 있습니다. 디자인 캔버스 원본은 보지 못해서, 설계와의 비교는 프론트 README, 코드, 블루프린트를 기준으로 했습니다.

## 1. 이번에 서버에 만든 것

| 기능 | 내용 |
|---|---|
| 회사 정책 엔진 | 콘솔에서 만든 규칙(단어 목록, 패턴, 말로 설명, 기본 정보의 처리 방식)을 저장하고, 초안 → 승인 → 버전으로 적용합니다. 롤백도 됩니다. 적용하면 확장과 채팅 프록시 모두 다음 요청부터 바뀝니다 |
| 기본 규칙 켜고 끄기 | 기본 규칙과 업종 항목을 하나씩 끌 수 있습니다. 요청과 답변 검사 양쪽에 적용됩니다 |
| `log` 처리 | 바꾸지 않고 보내되 기록만 남깁니다. 새 규칙을 시험할 때 씁니다 |
| 기본 규칙 목록 API | 프론트가 고정 목록을 들고 있던 걸 서버가 내려줍니다. 탐지 규칙이 늘면 목록에 빠지지 않도록 테스트가 막습니다 |
| 통계·기록 API | `since/until`, 총건수, 사이트·확장 버전, 가린 요청 수, p95, 한국 시간 버킷, 분 단위 (이전 작업) |
| 오류 형식 | 인증 실패와 입력 오류도 `{"error":{...}}`로 통일, 깨진 본문은 500이 아니라 400 |
| 프론트 연결 | 정책 엔진, 기본 규칙, 실시간 분당 그래프, 가림률, p95를 mock에서 실제 API로 교체 |
| 실행 도구 | `dev.bat`(서버 + 콘솔 한 번에), `scripts/seed_demo.py`, `scripts/try_text.py` |
| 도구를 쓰는 에이전트 | 모델은 가려진 값만 보고 앱은 `tool_calls`에서 진짜 값을 받습니다. 도구 결과는 키 이름으로도 가립니다 (`docs/API.md` 1-2, `scripts/agent_demo.py`) |
| 접속 키 | `GATEWAY_API_KEYS`로 앱·확장·시연 화면을 막고, 호출한 앱 이름을 감사 기록에 남깁니다 (`docs/API.md` 0) |
| 사내 앱 시연 화면 | `/demo`: 직원이 쓴 글, 바깥 모델이 받은 글, 복원된 답을 나란히 보여 줍니다 |
| 배포 | Dockerfile 한 이미지에 게이트웨이와 콘솔을 담아 Railway에 올렸습니다 (`docs/DEPLOY.md`), CI가 이미지를 실제로 빌드해 확인합니다 |
| 규칙 보완 | 고객님·회원님, 전화번호 표기, "비밀번호는 …" (아래 3번 표) |

## 2. 프론트가 설계와 다르거나 부족한 점

| 구분 | 내용 |
|---|---|
| 확장 안 화면 없음 | 디자인의 U1~U6(검토 창, 차단 안내, 예외 요청 등)과 팝업 개선은 만들지 않았습니다. 확장은 지금 `alert()`와 단순 팝업입니다. 규칙의 "보내기 전에 검토 창 띄우기", "예외 요청 받기", "알림" 옵션은 저장만 되고 아무 동작도 안 합니다 |
| 아직 mock | 로그인·2단계 인증, 구성원·가입 승인, 예외 요청, 설정, 관리자 작업 기록, 이상 징후, 교육 대상·Slack, 부서별 표, 정기 리포트, 포털(U7~U9), "잘못 찾은 비율". 새로고침하면 처음으로 돌아갑니다 |
| 규칙 순서 문구 | 정책 엔진 화면은 "위에서부터 확인 · 먼저 맞는 규칙 적용"이라고 쓰여 있지만 서버는 모든 규칙을 같이 적용합니다. 겹치면 차단이 이기고, 그다음 긴 쪽이 이깁니다. 순서를 진짜 우선순위로 쓸지 문구를 바꿀지 정해야 합니다 |
| 부서별 적용 | 화면에서 부서를 골라도 서버는 누가 보냈는지 몰라서 전사에 적용합니다. 안내 문구를 넣어 뒀습니다 |
| 기본 규칙의 "회사 업종만 켜짐" | 디자인은 회사 업종 항목만 켜져 있지만, 서버에는 회사 업종이라는 값이 없어서 전부 켜진 상태로 보입니다. 게다가 업종 항목은 요청이 업종을 지정해야(확장 팝업에서 체크) 동작합니다. 콘솔에서 켜 둬도 팝업에서 업종을 안 고르면 적용되지 않습니다. "업종은 회사가 정한다"로 바꿀지 결정이 필요합니다 |
| "몇 분 안에 받아요" | 적용 확인창에 "직원 확장이 몇 분 안에 받아요"라고 되어 있지만, 확장이 매 전송마다 서버에 묻기 때문에 적용은 즉시입니다. 문구 수정 대상입니다 |
| 블루프린트 범위 밖 | 가입 승인, 회사 코드, 구성원 관리, 포털은 블루프린트가 "발표용 확장 시나리오로만"이라고 한 영역입니다. 화면은 있지만 서버를 만들지 않는 편이 맞습니다 |
| 블루프린트에 있는데 약한 것 | "산업 선택 UI"는 확장 팝업에만 있고 콘솔에는 없습니다. "범용 vs 템플릿 탐지율 비교표"는 리포트의 규칙별 정확도로 있지만, 규칙(라벨)별이 아니라 업종별 행입니다 |
| 배포 구성 | 정적 호스팅, HTTPS, CORS 원본은 정해지지 않았습니다. `npm run preview`도 3000 포트를 씁니다 |
| 미검증 | Safari, Firefox, 화면 낭독기, 실제 외부 LLM으로 쌓인 대량 데이터 (프론트 README) |

## 3. 규칙에 보완이 필요한 점

현실적인 문장 23개(잡아야 하는 것)와 27개(건드리면 안 되는 것)로 확인했습니다. 제가 직접 돌린 결과입니다.
규칙 파일과 탐지 코드는 팀원 담당이라 고치지 않고 제안만 적습니다.

**놓치는 것**

| 입력 | 지금 | 제안 |
|---|---|---|
| `홍길동 고객님께 안내` | **고침.** 이름 뒤 `고객님·회원님·환자분·보호자님·담당자님`을 인식합니다 | — |
| `010 1234 5678`, `010.1234.5678`, `+82-10-1234-5678`, `02-1234-5678`, `031-123-4567` | **고침.** 공백·점 구분, 국제 표기, 지역번호 유선(마지막 네 자리 앞에 구분자가 있을 때만)을 인식합니다. 구분자 없는 숫자 나열은 전화로 보지 않습니다 | — |
| `비밀번호는 Abc12345! 입니다` | **고침.** `비밀번호/비번/패스워드` + `은/는/이/가` 뒤의 영문·숫자·기호 값을 차단합니다 (숫자나 기호가 있어야 하고, 한글 값이나 `required` 같은 단어는 제외) | — |
| `9001011234567` | 못 찾음 (하이픈 없는 주민번호) | 13자리면서 생년월일과 검증 숫자가 맞을 때만 |
| 카드번호, 계좌번호, 주소, 내부 IP | **업종 템플릿을 켜야만** 찾음. 콘솔 디자인은 이 셋을 기본 정보로 보여줌 | 카드번호(검증 숫자 확인), 계좌번호(은행명이 앞에 있을 때), 도로명 주소, 사설 IP 대역을 기본 규칙으로 올리기 |
| 직함 없는 이름(`제 이름은 최민수입니다`), 영문 이름 | 못 찾음 | 알려진 한계. `LOCAL_LLM_MODEL`을 켜야 함 |

**잘못 찾는 것**

| 입력 | 지금 | 제안 |
|---|---|---|
| `문서번호 123-45-67890를 참고` | 사업자번호로 가림 | 사업자번호는 검증 숫자 공식이 있습니다. 맞을 때만 가리거나 `사업자`, `등록번호` 같은 말이 가까이 있을 때만 |
| `이상한 과장님이 오셨다` | `이상한`을 이름으로 가림 | 이름 뒤 불용어에 `-한`, `-운`으로 끝나는 형용사 걸러내기 |

나머지 24개 평범한 문장은 모든 업종을 켜도 건드리지 않았습니다(주문번호 문장 1개는 이커머스 업종을 켰을 때만 가려지는데, 의도대로입니다). gitleaks 쪽(AWS, GitHub, Slack, OpenAI, Google 키, JWT, DB 주소, 개인 키 블록)은 모두 잡았습니다.

주의할 점이 하나 있습니다. 사업자번호나 주민번호에 검증 숫자를 도입하면 문서와 테스트에 쓴 가짜 값(`123-45-67890`, `000000-1000000`)은 통과하지 못합니다. 규칙과 같이 테스트 값도 검증을 통과하는 가짜 번호로 바꿔야 합니다.

**업종 템플릿**: 8개 모두 자체 테스트 100%이고 평범한 문장에서 오탐은 없었습니다(주문번호는 업종을 켰을 때만, 의도대로). 다만 테스트 문장이 업종당 3~17개라서 실제 문서의 다양한 표기는 아직 검증되지 않았습니다. 의료 3개, 화장품 4개로 샘플이 가장 적습니다.

## 4. 개선점

| 우선순위 | 내용 |
|---|---|
| 1 | **사용자 식별**: 확장이 누구인지(로그인 토큰) 서버가 알아야 부서별 규칙, 예외, 구성원, 교육 대상, 포털이 전부 의미를 가집니다. 지금 mock인 기능의 대부분이 이 하나에 막혀 있습니다 |
| 2 | **배포 가능하게**: 확장의 게이트웨이 주소가 `localhost:8000`으로 고정입니다. 회사 서버에 올리려면 주소를 설정으로 빼고(`optional_host_permissions`로 허용 요청), HTTPS를 붙이고, 콘솔을 정적으로 올리고, `GATEWAY_CORS_ORIGINS`를 맞춰야 합니다. 직원마다 localhost에 게이트웨이를 띄우는 방식이면 서버 배포는 필요 없지만, 정책을 중앙에서 관리할 수 없습니다 |
| 3 | **서버 인증 (일부 완료)**: 앱·확장·시연 화면은 `GATEWAY_API_KEYS`의 접속 키로 막을 수 있습니다 (`docs/API.md` 0). 콘솔 로그인은 아직 가짜이고 관리자 쪽은 `GATEWAY_ADMIN_TOKEN` 하나입니다. 키별 사용 한도와 요청 횟수 제한은 없습니다. 실제 LLM을 붙이기 전에 키를 반드시 켜세요 |
| 4 | **프로세스 하나로만 실행**: 정책은 SQLite에 저장되지만 적용된 규칙은 프로세스 메모리에 올려 둡니다. `uvicorn --workers 2` 이상이나 서버 여러 대로 띄우면 한쪽에서 적용한 규칙이 다른 쪽에 안 퍼집니다. Dockerfile은 기본이 한 프로세스라 지금은 문제없습니다 |
| 5 | **사용자 정의 패턴의 위험**: 정규식 패턴은 관리자가 쓰지만, 잘못 쓰면 서버를 느리게 만들 수 있습니다(파이썬 `re`는 시간 제한이 없음). 관리자만 접근하게 두는 게 전제입니다 |
| 6 | **확장**: 실제 chatgpt.com, claude.ai 화면 검증(조원 A), 파일·이미지 첨부 검사, 확장 안 검토 창, 내부 모델 경로가 없을 때 `internal_only` 항목이 그냥 차단되는 점의 안내 |
| 7 | **데이터 보관**: 보관 기간 설정이 mock입니다. 감사 로그를 지우는 기능이 없습니다 |
| 8 | **복원 매핑**: 매핑(vault)이 서버 메모리에 30분만 있어서 서버를 재시작하면 이전 답변의 이름표를 복원하지 못합니다 |

## 5. 서버에 아직 없는 기능

| 기능 | 먼저 정해야 할 것 | 규모 |
|---|---|---|
| 콘솔 로그인·세션·2단계 인증 | 계정 저장소(회사 SSO를 쓸지) | 중 |
| 구성원·가입 승인·회사 코드 | 사용자 식별 방식 | 중 |
| 예외 요청과 허용 기간 적용 | 사용자 식별 (요청한 사람만 통과시켜야 함) | 중 |
| 부서별 정책 적용, 부서별 집계 | 사용자·부서 정보의 출처 | 중 |
| 설정 (메일 제한, 잠금, 보관 기간, 일시 중지) | 로그인 | 소 |
| 관리자 작업 기록 | 로그인 (누가 했는지) | 소 |
| 이상 징후, 교육 대상 후보, Slack | 사용자 식별, Slack 연동 | 중 |
| 정기 리포트 발송 | 메일·Slack 연동 | 중 |
| 규칙(라벨)별 정확도 | 템플릿 테스트에 라벨 표시 (`detect` 값마다 어느 항목인지) | 소 |
| 회사 업종 설정 | 위 "기본 규칙" 결정 | 소 |

사용자 식별과 로그인 방식이 정해지지 않은 상태에서 이 기능들을 서버에 만들면 나중에 다시 만들어야 해서 이번에는 진행하지 않았습니다.

## 6. 검증 결과 (최근 상태)

- 서버 테스트 196개, 템플릿 9개 점검, 프론트 `tsc`·`eslint`·테스트 22개·빌드, 확장 단위 테스트 8개 통과. CI가 PR마다 같은 것과 Docker 이미지 빌드·기동 확인을 돌립니다.
- Railway 배포본에서 확인: `/health`, 콘솔, `/demo`, 관리자 토큰 차단, 가림·복원·차단, 도구 호출 시연.
- 실제 claude.ai에서 확장의 가림·복원·배지 확인. chatgpt.com은 입력창 추정을 넣은 뒤 다시 확인하지 못했습니다.
- 확인하지 못한 것: 실제 외부 LLM 호출(모든 시험이 가짜 모델), Chrome에 로드한 확장의 접속 키 칸, 정책이 재배포 뒤에도 남는지(관리자 토큰이 필요해 직접 확인해야 함).
