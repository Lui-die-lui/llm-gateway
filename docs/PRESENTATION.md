# 발표 준비와 시연 시나리오

발표 전에 한 번, 위에서부터 순서대로 하세요. 모든 값은 가짜입니다 (이름 · 번호 · 주소 · 키).

## 1. 데이터 넣기

콘솔에 보이는 숫자와 목록은 전부 서버가 저장한 실제 기록입니다. 발표용으로 채우려면 `scripts/seed_presentation.py`를 씁니다. 같은 요청 경로(`/v1/sanitize`, `/v1/exceptions`)를 그대로 지나가므로 가려진 종류와 개수가 실제와 똑같이 기록됩니다. 프롬프트 원문은 저장되지 않습니다.

```bash
python scripts/seed_presentation.py                     # 무엇을 넣을지만 보여 줌 (아무것도 안 씀)
python scripts/seed_presentation.py --yes --reset       # 이 PC의 DB를 비우고 채움 (게이트웨이를 먼저 끄세요)
python scripts/seed_presentation.py --yes --reset --api https://<배포 주소> --admin-token <토큰> [--key gw_...]   # 배포 서버에 채움
```

- 이 PC에 채우면 기록이 **최근 7일에 분산**되어 그래프가 자연스럽습니다 (평일 낮에 많고 주말엔 적게). 배포 서버에는 서버가 시각을 정하므로 모두 "지금"으로 들어갑니다.
- `--client-id b-...`: 발표에 쓸 **브라우저의 id**를 주면 그 브라우저의 확장에서 예외 요청 결과 팝업과 남은 시간 칩이 보입니다. id는 확장 팝업의 "자세히 보기" 링크 끝 `?cid=` 뒤 값입니다. 안 주면 콘솔에서만 보이는 시연 계정으로 들어갑니다.
- `--with-anomaly`: 방금 시크릿 3번 차단 기록을 넣어 콘솔 실시간 화면에 HIGH 이상 징후가 바로 뜨게 합니다. 빼면 발표 중에 직접 만들어 보일 수 있습니다 (아래 5번).
- 이미 데이터가 쌓여 있다면 `--reset`이 비웁니다. 콘솔의 `요청 비우기`, `기록 비우기` 버튼과 같은 동작입니다 (되돌릴 수 없음).

넣는 내용: 최근 7일 프롬프트 약 190건(그대로 통과 · 가림 · 시크릿 차단, 업종 9개), 구성원 6명 + 가입 승인 대기 2명(가짜 이름, example.com 메일), 예외 요청 5건(대기 1 · 24시간 승인 1 · 1회 승인 1 · 반려 1 · 1시간 승인 1건은 이미 끝남).

## 2. 발표 직전 점검 (3분)

1. 서버: `http://<주소>/health` 가 `{"status":"ok"}`.
2. 확장: `chrome://extensions`에서 새로고침, ChatGPT 탭도 새로고침. 팝업이 "게이트웨이 연결됨"이고 "이 탭 상태"에 입력창이 ✓.
3. 서버에 접속 키가 있으면 팝업 연결 설정의 "접속 키"에 `gw_...`를 넣었는지(없으면 401).
4. 콘솔: `admin@example.com` / `test1234`로 로그인해 개요에 숫자가 있는지.

## 3. 시나리오 (약 8분)

### A. 가리기와 복원 (확장, ChatGPT)
1. 입력: `고객 홍길동 메일 kim@corp.co.kr 로 보내줘` 후 Enter → **검토 창**이 뜹니다. 항목마다 자리표시자 / 대체어 / 그대로 두기를 고르고 미리보기가 바뀝니다. "적용하고 보내기".
2. ChatGPT가 답하면 화면에서는 **원래 값으로 복원**되어 보입니다(`홍길동`, `kim@corp.co.kr`). 모델은 `[사람_1]`만 받았습니다. 입력창 위 "N개 바꿔서 보냄"을 누르면 바꾼 내역(마스킹된 값만).
3. 한 번 더: `010-2345-6789`를 붙여넣기만 해도(편집 없이) 입력창 위에 알림이 뜹니다.

### B. 막기 (시크릿)
1. 입력: `API 키 sk-abcdefghijklmnopqrstuvwx1234 가 왜 거절되나요?` → "전송을 막았어요". 시크릿은 가려도 보내지 않습니다. 입력한 글은 그대로 남아 있습니다.

### C. 예외 요청 → 승인 → 남은 시간 (확장 + 콘솔)
1. 막힘 안내의 "예외 요청"으로 요청서를 보냅니다 (사유 20자 이상).
2. 콘솔 `예외 요청`에서 요청을 열어 **기간(1시간 등)을 고르고 승인**, 또는 메모와 함께 **반려**합니다.
3. ChatGPT 화면 오른쪽 위에 **결과 팝업**(반려면 사유 포함)이 뜹니다. 채팅 화면이 앞에 없으면 시스템 알림으로 옵니다.
4. 승인되면 입력창 **왼쪽**에 `남은 시간 59분 …` 칩이 생기고 1초마다 줄어듭니다. 누르면 어떤 항목 · 사이트 · 기간인지와 관리자 메모가 펼쳐집니다. 규칙이 여러 개면 가장 먼저 끝나는 하나만 보입니다.
5. 같은 항목을 보내면 가려지지 않고 그대로 나가며, **1회 허용은 쓰는 즉시 칩이 사라집니다**.
6. 콘솔 `기록`에서 그 기록을 눌러 `예외 요청 보기`로 승인 근거를 바로 확인합니다.

### D. 콘솔 둘러보기
- `개요` → 지표 · 시간대 그래프 · 많이 찾은 정보 종류. `실시간 모니터링` → 분당 그래프와 **이상 징후**(시크릿 3번 반복 시 HIGH, 가림 급증 시 MEDIUM). 카드의 `기록 보기`, `확인 처리`.
- `정책 엔진 2 · 기본 규칙` → 업종별 위험 키워드와 예시 문장. 규칙을 끄고 "적용" → 몇 분 안에 확장이 받습니다.
- `분석 리포트` → 7일 추이와 규칙별 정확도.

### E. ChatGPT에 연결된 메일을 보낼 때
1. `고객 홍길동에게 사과 메일 초안을 써서 kim@corp.co.kr 로 보내줘`처럼 요청하면, 모델이 만든 메일 카드의 받는 사람 · 본문도 **원래 값으로 복원**되어 보입니다 (입력칸 값 포함).
2. 카드의 **보내기** 버튼을 누르면 확장이 한 번 확인합니다. 화면이 복원돼 있어도 사이트가 카드 뒤에서 쥔 값은 가려진 값일 수 있어서, 받는 사람과 내용을 확인한 뒤 진행하라는 안내입니다.
3. 한계: 모델이 메일을 사이트 서버 안에서 바로 실행하면 그 인자는 브라우저를 거치지 않아 확장이 바꿀 수 없습니다. 이 경우는 카드를 보고 직접 고쳐 보냅니다.

## 4. 시연 중 흔한 문제

| 증상 | 원인과 해결 |
|---|---|
| 전송 때 `접속 키가 없거나 맞지 않아…` | 서버에 접속 키가 켜져 있음 → 팝업 연결 설정의 "접속 키" |
| 답변이 `[사람_1]` 그대로 | 이 탭이 기억하는 값은 1시간, 서버 매핑은 30분(재시작하면 사라짐). 새 대화에서 다시 보내기. 모델이 자리표시자를 안 쓰면 "자리표시자를 그대로 써서 답해줘" |
| 이상 징후가 안 뜸 | 시크릿이 든 글을 **같은 곳에서 10분 안에 3번** 보내야 함 (`--with-anomaly`로 미리 넣을 수 있음) |
| 남은 시간 칩이 안 보임 | 승인된 요청의 **사이트**가 지금 사이트와 같아야 하고, 이 브라우저(id)가 보낸 요청이어야 함 |
| 개요가 텅 빔 | 기록이 없음 → 1번으로 데이터 넣기. 개요 기본이 "오늘"이라 새벽에는 적게 보임 → `7D`로 |

## 5. 끝나고 되돌리기
콘솔 `기록 비우기`, `요청 비우기`, 또는 `python scripts/reset_data.py --yes`로 비웁니다.
