## 1장 · 표지 (15초)

안녕하세요. 전체 구조와 서버 쪽을 맡은 ○○○입니다.

저희가 만든 것은 한 줄로, 직원이 ChatGPT에 글을 보내기 전에 그 글을 한 번 걸러 주는 문입니다. 이 문을 누가 쓰고, 안에서 어떻게 돌아가는지 설명하겠습니다.

## 2장 · 문제 정의 (35초)

직원들은 이미 ChatGPT를 씁니다. 문제는 거기에 뭘 붙여넣느냐입니다.

`[세 카드]` 고객 이름과 연락처가 든 메일, 비밀번호와 서버 주소가 든 오류 로그, 그리고 화장품 배합표나 계좌번호 같은 회사 기밀. 이런 것들이 그대로 들어갑니다.

한 번 나간 글은 되돌릴 수 없습니다. 그렇다고 ChatGPT를 못 쓰게 할 수도 없습니다. 그래서 보내기 전에 한 번 검사하는 단계가 필요합니다.

## 3장 · 사용 대상 (35초)

쓰는 사람은 셋입니다.

`[크롬 확장]` 첫째, 웹에서 ChatGPT를 쓰는 직원입니다. 크롬 확장 하나만 깔면 됩니다. 평소처럼 쓰면 보내는 순간 자동으로 검사됩니다.

`[OpenAI 호환 API]` 둘째, 회사 안에서 AI 프로그램을 만드는 개발자입니다. 코드에서 주소 한 줄만 바꾸면 그 프로그램이 보내는 글도 모두 같은 검사를 거칩니다.

`[웹 콘솔]` 셋째, 보안 담당자입니다. 관리 화면에서 규칙을 정하고, 예외를 승인하고, 뭐가 몇 건 걸렸는지 봅니다.

## 4장 · 시스템 구조 (1분 30초)

그림을 왼쪽에서 오른쪽으로 따라가겠습니다.

`[왼쪽 두 입구]` 입구는 방금 말한 둘입니다. 크롬 확장과 회사 프로그램. 둘 다 같은 서버로 들어옵니다. `[가운데 상자]` 서버는 한 대이고, 입구가 달라도 안에서 처리하는 방법은 똑같습니다.

서버 안에서는 네 단계를 거칩니다.

`[① 탐지]` 첫째, 찾기입니다. 글 안에서 민감한 값을 찾습니다. 규칙은 세 겹입니다. 주민번호나 전화번호처럼 어느 회사나 같은 것, 비밀번호나 API 키 같은 것, 그리고 배합표나 계좌번호처럼 업종마다 다른 것. 숫자만 보면 헷갈리는 값은 앞뒤에 "서버", "계좌" 같은 단어가 있는지도 같이 봅니다. 그래서 버전 번호 10.2.3.4는 IP로 잡히지 않습니다.

`[② 판정]` 둘째, 어떻게 할지 정하기입니다. 찾은 값마다 셋 중 하나입니다. 가려서 보내거나, 아예 못 보내게 막거나, 승인받은 것은 그대로 보내되 기록에 남깁니다. 비밀번호 같은 건 가려도 안 되니까 막습니다.

`[③ 가림]` 셋째, 가림입니다. 값을 `[사람_1]`, `[이메일_1]` 같은 이름표로 바꿉니다. 같은 값은 같은 번호를 받습니다. 그래서 모델은 "같은 사람 얘기구나"는 알지만 누군지는 모릅니다.

`[④ 전송]` 넷째, 보내기입니다. `[오른쪽 외부 LLM]` 바깥 모델은 가려진 글만 받습니다. 돌아온 답변도 한 번 더 검사합니다.

그럼 원래 값은 어디 있느냐. 서버 메모리에만 잠깐 있다가 사라집니다. 회사 프로그램은 요청 하나 끝나면 바로, 크롬 확장은 길어야 30분입니다. 파일로 저장하지 않습니다.

`[하단 기록]` 기록에는 뭐가 몇 건 걸렸는지, 어느 사이트에서 보냈는지만 남습니다. `[미기록 원문]` 원래 글은 남기지 않습니다. 그래서 기록이 새도 민감한 값은 없습니다.

`[하단 배포]` 서버는 Docker로 묶어 Railway에 올렸고, 코드를 합치기 전에 자동 시험이 돌아갑니다. 서버 시험만 275개입니다.

## 5장 · 처리 방식 (35초)

왜 그냥 지우지 않고 이름표를 쓰는지입니다.

`[왼쪽 원문]` "고객 홍길동에게 kim@corp.co.kr로 사과 메일 작성"이 들어오면 `[오른쪽]` 모델에는 "고객 `[사람_1]`에게 `[이메일_1]`로 사과 메일 작성"으로 갑니다.

그냥 "XXX에게 XXX로"라고 보내면 모델은 뭘 해야 할지 모릅니다. 이름표는 "여기는 사람, 여기는 이메일"이라는 종류만 알려 줍니다. 모델은 메일을 쓸 수 있고, 실제 이름과 주소는 끝까지 모릅니다. 사용자는 받은 초안의 이름표 자리에 실제 값을 넣어 쓰면 됩니다.

이 방식은 Presidio 같은 유명한 개인정보 가림 도구가 쓰는 방식과 같습니다. 저희는 그 도구를 가져온 게 아니라 같은 방식을 한국어와 업종에 맞춰 직접 만들었습니다.

## 6장 · 적용 화면 · 크롬 확장 (30초)

실제 ChatGPT 화면입니다. 값은 다 예시입니다.

`[①]` 이름과 메일 주소를 넣고 보내면 채팅창에는 `[사람_1]`, `[이메일_1]`로 가려져서 올라갑니다.

`[②]` 모델은 누군지 모른 채로 메일 초안을 씁니다.

`[③]` 글을 쓰는 중에 API 키나 IP가 들어가면 보내기 전에 입력창 위에 경고가 뜨고, 그래도 보내면 막힙니다.

한계도 있습니다. 답변 속 이름표를 원래 값으로 바꿔 보여 주는 기능은 아직 안정적이지 않아 이번 발표에서는 뺐습니다. 그리고 ChatGPT가 Gmail 같은 다른 서비스로 직접 보내는 경우에는 이름표가 그대로 전달됩니다. 이건 크롬 확장이 끼어들 수 없는 구간이라, 그런 경우는 회사 프로그램 경로를 써야 합니다.

여기까지가 제 파트입니다. 다음은 ○○○이 탐지 규칙과 업종 템플릿을 이어서 설명하겠습니다.

## 예상 질문

- **왜 AI로 찾지 않고 규칙으로 찾나요?** 민감한 값을 찾으려고 그 값을 또 다른 AI에 보내면 앞뒤가 안 맞습니다. 규칙은 같은 글에 늘 같은 결과가 나오고, 왜 걸렸는지 설명할 수 있습니다.
- **두 입구의 처리가 정말 같나요?** 찾고, 정하고, 가리는 코드는 하나입니다. 다른 건 원래 값을 메모리에 두는 시간뿐입니다.
- **같은 사람이 두 번 나오면요?** 같은 값은 같은 이름표입니다. 그 요청 안에서 `[사람_1]`은 늘 같은 사람입니다.
- **기록이 새면요?** 원래 글은 없습니다. 종류와 건수, 사이트만 있습니다.
- **복원은 안 되나요?** 서버에는 이름표를 원래 값으로 되돌리는 기능이 있고 시험도 통과합니다. 다만 ChatGPT 화면 쪽에 제약이 있어 이번 발표 범위에서 뺐습니다.
- **Presidio를 쓴 건가요?** 아닙니다. 같은 방식을 직접 만들었고, 비밀번호 찾는 규칙만 오픈소스에서 가져왔습니다.
